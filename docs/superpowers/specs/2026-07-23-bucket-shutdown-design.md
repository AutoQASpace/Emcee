# Graceful-завершение билдера после закрытия result stream (16.0.12)

Дата: 2026-07-23. Статус: дизайн одобрен, ждёт ревью спеки.

## Контекст

Бакет (все тесты списком в `OnlyTestIdentifiers` xctestrun) исполняется одним автономным
процессом xcodebuild («билдер»). Emcee после старта — пассивный наблюдатель: читает файл
`result_stream.json` (tail → `BlockingArrayBasedJSONStream` → `JSONReader` →
`JsonToResultStreamEventStream`) и ждёт терминации. Корневая запись xcresult пишется
билдером в самом конце (финализация); до неё бандл нечитаем.

Доказано (инцидент 22.07, бакет 909F853E; код — от противного): при живом билдере чтение
стрима завершается **только** исключением `JSONReader` на синтаксически битом JSON.
Текущий код (Fix #1.3) трактует любое закрытие стрима как конец прогона и убивает билдер
(`Runner.swift:252-256` → `cancel()` → SIGTERM, доставляемый после CLT-фикса `f77f0c0`).
Результат: здоровый билдер расстрелян до финализации → бандл труп → плагин стабит весь
бакет в Allure (включая реально зелёные), плюс мусорные exceptions
`Error parsing xcresult bundle … exit code 64` от чтения недописанного бандла.

Причина порчи JSON — открытый **дефект A**, расследуется отдельно (см. «Вне скоупа»).

## Матрица сценариев (зафиксированные решения)

| Сценарий | Решение |
|---|---|
| S1: билдер мёртв, ошибки нет (штатный, ~99%) | поведение не меняется (ожидание = 0) |
| S2: билдер мёртв, ошибка чтения (краш) | как сегодня: бандл возможно бит, ретраи закроют |
| S3/S6: билдер жив, ошибка чтения (короткий/длинный хвост) | ждать по **прогрессу** до естественного выхода; дубли хвоста от queue-ретраев — **терпим** (решение пользователя) |
| S5: билдер жив и завис (нет прогресса) | единственный легитимный килл: SIGINT → 15с → SIGKILL |

Килл как реакция на закрытие стрима упраздняется. Киллы остаются: silence/preflight/
postflight-таймауты (`Runner.swift:163,215,219`), прогресс-стоп (новый), shutdown воркера.

## Изменения

### 1. `Sources/AppleTools/XcodebuildBasedTestRunner.swift` (completion `streamContents`, :107-120)

Было: `error → лог → readResultBundle (по недописанному бандлу) → closeStream`.

Станет:
1. При error: лог «Result stream error» + размер/mtime `result_stream.json` (улика для дефекта A).
2. `RunnerProcessProgressWaiter.waitForExit(...)` — ждать собственного выхода билдера.
3. `readResultBundle(...)` — бандл к этому моменту финализирован (exit-64 мусор исчезает).
4. `testRunnerStream.closeStream()`.

### 2. Новый тип `Sources/AppleTools/RunnerProcessProgressWaiter.swift`

Ответственность одна: дождаться выхода процесса, пока тот показывает прогресс, иначе убить.

- Прогресс = максимум из (mtime/размер `result_stream.json`) и (максимальный mtime по
  неглубокому обходу `resultBundle.xcresult`: сам каталог + записи первого уровня +
  `Data/` — дёшево, без рекурсии по тысячам файлов).
- Опрос каждые `pollInterval = 5с`, пока `isProcessRunning`.
- Прогресс стоит ≥ `progressStallTimeout = 300с` → лог + `interruptAndForceKillIfNeeded()`
  (SIGINT, авто-SIGKILL через 15с) + `waitForProcessToDie()`.
- `hardCap = 1800с` суммарного ожидания — страховка от «вечного прогресса».
- Константы именованные, в конфиг не выносим (YAGNI).
- Юнит-тесты: выходит сам / прогресс идёт / прогресс встал / hard cap.

### 3. `Sources/Runner/Runner.swift` (блок Fix #1.3, :252-256) + invocation

- `cancel()+wait()` → `wait()` (процесс уже мёртв, мгновенно) + `performPostRunCleanup()`.
- `performPostRunCleanup()` — новый метод `TestRunnerRunningInvocation` (протокольный
  дефолт — пустой): в `ProcessControllerWrappingTestRunnerInvocation` зовёт только
  in-sim зачистку (`onCancel` → существующий `InSimulatorApplicationTerminator`), без килла.
- Runner больше не убивает процессы на штатном пути вообще.

## Известное ограничение (принято осознанно)

Postflight-таймер (`testRunnerMaximumSilenceDuration` = 900с, testargbase) меряет тишину по
видимым событиям стрима: после ошибки парсера события не приходят, и на хвосте длиннее
~900с он стрельнёт свой `cancel()` до финализации (стабы + ретраи, как сегодня).
Прогресс-путь защищает хвосты до ~15 минут; сверх — принимаем. Лечится подъёмом silence
в testargbase, если заболит.

## Вне скоупа

- **Дефект A** (что портит JSON в result_stream.json) — отдельное расследование;
  первый шаг заложен здесь же: расширенный лог при «Result stream error».
- Backfill результатов хвоста из финализированного бандла (устранение дублей queue-ретраев)
  — возможная следующая итерация после обкатки.
- Судьба веток Emcee (`AQA-7794-scheme-approvals` с коммитами `b322751f`, `1f35c2c6`) —
  отдельное решение пользователя.
